- **Severity:** High. **Blocker before M3.**
- **Sections:** §5, §6, §11 flow 3, M3.
- **Problem:** The plan describes shutdown for cancel, timeout, and output limits, but not for ordinary exit. A background process can inherit stdout, so pipe EOF may never arrive after the root process exits **[Inference]**.
- **Failure scenario:** A build exits 0 while a compiler server or watcher holds the pipe open. Waiting for EOF stalls until the timeout, and the harness reports a timeout for a successful build. If it instead returns and leaves the job open, it breaks §1's "no persistent background commands".
- **Correction:**
  - Root process exit means the command finished, and its exit code is authoritative.
  - Then terminate remaining job members, recording the count.
  - Drain pipes for a short bounded period, then mark output incomplete if needed.
  - Confirm shutdown by querying job accounting. Do not rely only on completion-port messages, which Microsoft says are not guaranteed **[Doc]**.
  - Ensure a blocked pipe reader cannot stall process exit. Tokio's Windows stdio may use blocking threads **[Verify]**.
  - Extend flow 3 with a fixture where the root exits and a grandchild holds stdout.
  - Document that build servers are killed after each command, and that some processes are outside the job. For example, `Win32_Process.Create` children are not associated with it **[Doc]**. The caution in §6 about Unix escapes should apply to Windows too.

### OPUS-06: "Graceful stop" has no defined Windows mechanism

- **Severity:** High. **Blocker before M3.**
- **Sections:** §6, §9, M3.
- **Problem:** Windows has no direct SIGTERM equivalent for this tree. `CTRL_C_EVENT` cannot target a process group. `CTRL_BREAK_EVENT` reaches only processes sharing the caller's console **[Doc]**. The plan does not choose a console policy.
- **Failure scenario:** With `CREATE_NO_WINDOW`, the child does not share the caller's console, so nothing can be delivered and the graceful phase just waits out its timer **[Inference]**. With a shared console, the user's Ctrl+C reaches the child directly, racing the engine's ordered cancellation. If the harness has no console, for example under a host app, the mechanism also fails.
- **Correction:** Recommended for Windows v1: use `CREATE_NO_WINDOW`, skip the graceful phase, and cancel with `TerminateJobObject`, recording that the stop was forced and partial effects are possible. Reword the shared contract as "bounded stop, graceful where the platform supports it", so the Unix path can still use signals.

### OPUS-07: Windows command resolution and shell form are unspecified

- **Severity:** High. **Blocker before M3.**
- **Sections:** §5 `run_command`, M3, M6.
- **Problem:** Rust's `Command` appends only `.exe`. Other extensions must be explicit **[Doc]**. So `npm`, `npx`, `pnpm`, `yarn`, and many similar tools, usually `.cmd` shims on Windows, fail by bare name **[Inference]**. Batch arguments that cannot be escaped safely fail with `InvalidInput` **[Doc]**. The shell form names no interpreter, profile behavior, quoting, or script transport.
- **Failure scenario:** The model calls `npm` with `["test"]` and gets "program not found". It falls back to a script form it knows nothing about. It writes `npm install && npm test`, which fails under Windows PowerShell 5.1. M3 fixtures may pass while ordinary repositories fail.
- **Correction:**
  - Add a harness resolver that uses PATH and PATHEXT before approval. Show and bind the resolved absolute path.
  - Do not resolve bare names from the workspace. Run workspace programs only through an explicit relative path.
  - Map `InvalidInput` to a structured tool error.
  - Detect allowed interpreters at session creation and name them in the frozen tool description.
  - Run PowerShell with `-NoProfile -NonInteractive`. Pass scripts with `-EncodedCommand` or a temporary file outside the workspace. Show the script verbatim.
  - Add a `.cmd` shim fixture to the M3 gate.

### OPUS-03: The planned compaction shape is rejected when thinking blocks are replayed

- **Severity:** High. **Blocker before M5.**
- **Sections:** §8, M5.
- **Problem:** "Retain... recent complete exchanges" is keep-tail compaction. Replaying those turns' thinking blocks after a summary returns a 400 **[Doc]**. §8's clean-sequence fallback points the right way, but it reads as an exception. With always-on thinking, it is the normal case.
- **Failure scenario:** The constrained-context fixture passes against a scripted provider. Live, the first request after compaction fails on an enforced account. The new checkpoint is already active, so the session cannot continue.
- **Correction:**
  - Use synchronous compaction, only between closed tool batches.
  - Prefer simple compaction: a single summary message that includes the preserved user requirements. If recent turns stay, strip their `thinking` and `redacted_thinking` blocks.
  - Treat the compacted history as a new epoch with its own checkpointed `system` and tools.
  - Validate the first post-compaction request before discarding the ability to fall back to the prior context.
  - Reserve headroom so the summary request itself fits.
  - Borrow fx's numbers as starting values: trigger at 80% of usable input, keep about 5% recent history, and cap the handoff at 10%. fx also compacts and retries once on provider overflow **[Doc]**.

## 3. Non-blocking findings

Fix these inside the named milestone.

### OPUS-18: Context budgeting arrives too late and needs a correct token measure

- **Severity:** Medium. **Fix at M1.**
- **Sections:** §4, §8, M1, M5.
- **Failure scenario:** 60 previews of 64 KiB total about 3.75 MiB, or very roughly 1M tokens at 4 characters per token **[Inference]**. A 200K model overflows after about 12. Before M5, this appears as an unclassified 400. Once caching exists, a threshold based on `input_tokens` alone may never trigger, because that field excludes cached tokens **[Doc]**.
- **Correction:** Add a hard pre-send budget and a recoverable `context_limit` outcome at M1. Measure prompt size as `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`, then estimate only new content. Use `count_tokens` selectively. `GET /v1/models/{id}` can supply `max_input_tokens` and `max_tokens` **[Doc]**.

### OPUS-19: Prompt caching is absent

- **Severity:** Medium. **Fix at M1.**
- **Sections:** §4, §8, §9.
- **Failure scenario:** At the skill's cached Opus 5.5 prices, 30 requests with a 300K-token prompt cost about $36 uncached. They cost about $3.24 with one 5-minute cache write and 29 reads, ignoring prompt growth **[Inference from Doc prices]**. Users would reasonably abandon the tool on cost.
- **Correction:** Add a `cache_control` marker and log cache fields from M1. OPUS-02's frozen prefix supplies the necessary stability. Check prices at implementation time.

### OPUS-13: Output artifact protocol is undefined

- **Severity:** Medium. **Fix at M3.**
- **Sections:** §2, §5, §7.
- **Failure scenario:** Per-chunk durable tool-output events cause many fsyncs and a bloated database. Alternatively, output buffered in memory is lost in a crash, so §7 cannot show "captured output" for an unknown command.
- **Correction:** Spool each attempt to a file in the data directory as output drains. Keep chunk events ephemeral. At completion, flush the file, then commit its path, length, hash, and truncation state in one transaction. After a crash, show the spool labelled partial and unverified.

### OPUS-14: Windows path forms can bypass scope and credential checks

- **Severity:** Medium. **Fix at M1.**
- **Sections:** §5.
- **Failure scenario:** Name-based denial of `.env` may miss `.env.`, `.env::$DATA`, or an 8.3 alias **[Inference from the Win32 rules]**. `workspace.join(r"\Windows")` and `workspace.join("D:foo")` leave the workspace, and neither input counts as absolute on Windows **[Doc]**.
- **Correction:** Allow only normal path components. Reject prefixes, roots, `..`, colons, trailing dots or spaces, and reserved device names. After opening, check the handle's final path against scope and evaluate denial on that final name, case-insensitively. Apply the same denial to `search_text` and `list_files`, and do not follow links during traversal.

### OPUS-15: Approval needs a fixed target and better fidelity

- **Severity:** Medium. **Fix at M2 and M3.**
- **Sections:** §5, §6, §9.
- **Failure scenarios:** "Relevant file hash" has no defined meaning for commands, and a shell-form bare name may run a repository file instead of the expected tool **[Verify cmd.exe search order]**. Bidi or zero-width characters can make approved text read differently. A patch to `.git/config` or `.git/hooks` can create later code execution, and §5 limits only listing of VCS directories.
- **Correction:** Bind commands to resolved executable, full arguments or script, cwd, timeout, and environment changes. Show approval text in full, with non-printing characters visible. Deny built-in writes under `.git/` in v1. This is a fixed rule, not the risk classifier §1 excludes.

### OPUS-16: Engine progress can depend on a slow UI

- **Severity:** Medium. **Fix at M0 or M1.**
- **Sections:** §2.
- **Failure scenario:** `harness ask --json | slow-consumer` fills a bounded channel. If the coordinator awaits that send, cancellation and timeout handling stop too.
- **Correction:** The coordinator commits durable events and never awaits the UI. Subscribers catch up from `EventSequence`, and only ephemeral deltas may be dropped. Define behavior for a closed stdout pipe.

### OPUS-17: Test seams are not concrete enough for the promised failure flows

- **Severity:** Medium. **Fix at M0, applied per milestone.**
- **Sections:** §11.
- **Assessment:** §11 follows the minimal-functional-tests skill well: one canonical flow, public-interface tests, real SQLite, and no coverage target. Do not add broad suites. Four focused changes are needed:
  - **A permissive fake hides the worst bugs.** A scripted provider would accept the invalid histories in OPUS-01 through 03. Have the fake validate tool pairing and prefix immutability on each request. Keep SSE fixtures for the decoder.
  - **Crash and persistence failures need a defined technique.** Run flow 4 in a child process with a test-only abort point, then reopen through the public interface. For flow 5, `PRAGMA query_only` may produce real write failures without a store abstraction **[Verify]**.
  - **Flows 1 and 7 combine unrelated behavior.** Split scope escape from approval, and schema mismatch from locking. The skill says one flow should not combine unrelated capabilities.
  - **Add two assertions to existing flows, not new suites.** After a denied call, the next request is valid. A surviving grandchild does not hang completion.

### OPUS-20: HTTP requirements need specific settings

- **Severity:** Medium. **Fix at M1.**
- **Sections:** §3.
- **Failure scenarios:** reqwest's default policy follows up to 10 redirects, and its cross-origin stripping omits `x-api-key`, so the key could reach another origin **[Doc]**. A total `timeout` includes the body, so a long healthy stream is killed **[Doc]**.
- **Correction:** Use `redirect::Policy::none()`, `connect_timeout`, and an idle `read_timeout`. Bound the whole stream using the turn deadline. Mark the credential header sensitive. Decide explicitly whether system proxies apply.

### OPUS-21: Provider request defaults are missing

- **Severity:** Medium. **Fix at M1.**
- **Sections:** §1, §4.
- **Failure scenarios:** With no explicit API version, behavior drifts unnoticed. On `2026-10-21`, `temperature`, `top_p`, and `top_k` return 400 **[Doc]**. Opus 5.5 defaults effort to `medium`, and thinking display to `omitted`, so "streamed progress" can appear as a long silence **[Doc]**.
- **Correction:** Pin `anthropic-version`, send no sampling parameters, set effort explicitly, and set thinking display so progress is visible. Persist the model ID as well as the provider identity, and reject silent model changes on resume, since thinking blocks are model-bound **[Doc]**. Add an event that tells the UI an attempt's streamed text was discarded before a retry.

### OPUS-22: Staged replacement needs Windows specifics

- **Severity:** Medium. **Fix at M2.**
- **Sections:** §5, §7.
- **Failure scenario:** An antivirus scanner or editor briefly holds the target, so the rename fails **[Inference]**. A plain temp-and-rename may lose the original's ACLs or attributes. A crash leaves a temp file inside the repository.
- **Correction:** Use a recognizable temp name in the target directory, with bounded retry on sharing violations. Evaluate `ReplaceFileW` to preserve metadata **[Verify]**. Remove orphans from recorded intent during recovery, and never remove anything else.

### OPUS-23: Instruction precedence appears inverted for nested files

- **Severity:** Low to Medium. **Fix at M1.**
- **Sections:** §8.
- **Failure scenario:** §8's ordering makes nested instructions lowest, so a root rule overrides a package's more specific rule. AGENTS.md convention says the closest file wins, with explicit user prompts overriding all of them **[Doc]**.
- **Correction:** State that within project instructions the most specific applicable file wins. Everything remains below engine policy. Name the instruction filenames to load, which §8 does not specify.

### OPUS-24: Windows output decoding is unspecified

- **Severity:** Low to Medium. **Fix at M3.**
- **Sections:** §5.
- **Failure scenario:** Native tools may emit an OEM code page or UTF-16 when piped, so lossy UTF-8 decoding garbles paths and errors **[Verify]**.
- **Correction:** Keep raw bytes as stored. For display, try UTF-8, detect UTF-16 BOMs, then fall back to the console code page, and record the decoding used.

### OPUS-25: Internal consistency items

- **Severity:** Low. **Fix during revision.**
- **Items:**
  - §2 includes session deletion, but §9 has no command for it.
  - Linux has §6 design and an M6 qualification gate, but no milestone that builds it. Mark it post-v0.1 unless scheduled.
  - The 256 KiB tool-argument cap is smaller than the 1 MiB file limit, so large new files cannot be created in one call. State this as intended.
  - 30 requests and a 120-second default are low for real builds and tests. Keep them, but make hitting them resumable and easy to reconfigure.
  - `sessions list` and `session show` use inconsistent nouns.

## 4. Deferrable: do not add to the MVP

- **OPUS-D1:** Session-scoped approval of identical commands. Per-call approval is tedious but safe.
- **OPUS-D2:** `eager_input_streaming` and `strict: true`. Both are useful later. If eager streaming is added, the client must validate strictly **[Doc]**.
- **OPUS-D3:** Server-side compaction, context editing, task budgets, and refusal fallback models. Client-side compaction and a clear `refused` outcome suffice for v1.
- **OPUS-D4:** A full child-environment allowlist. Scrub provider secrets now, and document that other variables remain visible.
- **OPUS-D5:** Non-interactive environment defaults such as `GIT_TERMINAL_PROMPT=0`. Timeouts already bound the failure.
- **OPUS-D6:** Undo, a second provider, stress testing, TUI, and Linux in v0.1.
