## 8. Context and instructions

Instruction precedence: engine/system policy, explicit current user instructions, user-level preferences, then project instructions. Within project instructions the closest applicable nested `AGENTS.md` overrides its ancestors. Load the configured user-level file, project-root file, and applicable nested files; do not automatically load every vendor's instruction format. Load scoped instructions before exposing related files/tools. Snapshot content, origin, and hash for audit; append later discoveries without mutating an epoch's frozen prefix. Project text cannot grant permissions.

Use provider-specific token counting when available. Otherwise use a conservative estimate and reserve response/tool/schema headroom. Reject missing/invalid context-limit configuration; do not assume every model has the same limit. Use bounded ranges and output handles before summarizing conversation.

Enforce this pre-send budget from M1a/M1b, before compaction exists. Normalize total prompt usage per route, including cached tokens without double counting; do not copy an Anthropic-specific accounting formula into other adapters. Persist raw usage from the first request. Keep prefixes stable and enable only verified provider-supported caching options. Record cache usage when returned; do not send unsupported cache-retention parameters through ChatGPT plan access or promise unmeasured savings.

Budget the entire request, including the next complete tool-result batch, rather than treating each byte cap as sufficient. Pin current user constraints ahead of older summaries. If the smallest valid complete cycle cannot fit, return a context-limit outcome instead of splitting call/result pairs or silently dropping requirements.

Compact synchronously only between closed tool batches. Create a fresh context epoch with current requirements and a bounded textual handoff covering unresolved issues, decisions, modified paths, and observed results. Do not transplant old signed thinking/opaque blocks under the new prefix; recent exchanges inform the handoff rather than being blindly replayed. Preserve all original messages and opaque data in their original epoch. Reserve input headroom for the summary request itself, using bounded chunks if needed. Start with a conservative configurable threshold qualified against the chosen models.

Persist the candidate epoch/checkpoint before use while retaining the prior active epoch. Validate its first provider response before atomically promoting it and authorizing proposed tools. On failure retain the prior epoch; return recoverable `context_limit` if it cannot continue. Do not undo completed effects to fall back. Prefix/continuation errors require a corrected epoch, never fabricated signatures or blind retry. Expose the epoch change. Summaries cannot raise permissions. Semantic/vector memory is deferred. This preserves fx's distinction between original history and compacted context while defining our own valid continuation. [fx compaction](https://fx.sh/docs/using-fx/context-compaction)
