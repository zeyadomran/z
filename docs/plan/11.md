## 11. Minimal functional validation

Follow the supplied minimal-functional-tests skill. Exercise the public engine interface using real internal modules, temporary workspaces, and a real temporary SQLite database. Substitute the external model endpoint and control external failures/time explicitly. Do not mirror every engine test through CLI, database, and UI suites.

Canonical success flow: prompt → scoped inspection → approved patch → approved verification command → observable final result → close/reopen history. Extend this owner as milestones land.

Keep one engine-flow owner; do not duplicate the entire suite for each provider. Add focused wire-contract fixtures for each real adapter and one account-authentication flow for the distinct ChatGPT lifecycle. Parameterize the same bounded manual live-model qualification over both required providers. A controlled auth fixture cannot prove this user's real subscription eligibility.

Separate material failure flows, added when the behavior is implemented:

1. Denied or stale approval cannot cause an edit or command; subsequent provider continuation remains valid.
2. Truncated/malformed provider stream cannot execute partial tool calls; bounded retry preserves completed tool results.
3. Cancellation/timeout terminates the owned child tree and returns a truthful outcome with bounded output.
4. Crash recovery reconciles patches and refuses automatic replay of unknown command outcomes.
5. Failed persistence prevents new side effects and preserves a truthful uncertain result after an external effect.
6. Compaction failure preserves the previous history; successful compaction retains current requirements and complete call/result pairing.
7. A second process cannot start another active turn in the same workspace, including while its existing turn is suspended.
8. Scope escape or denied-path aliases are rejected consistently by reads, search, listing, and edits.
9. Schema mismatch cannot overwrite existing session data.

Extend the owning flows with the review corrections rather than creating duplicate suites: a partially completed multi-call batch resumes without repeated effects; a paused/dropped observer cannot prevent cancellation; parent death at process creation leaves no fixture child; normal launcher exit cannot leak a descendant; approved command normalization covers explicit batch handling; native patch qualification checks non-default ACL preservation. Use explicit fixture synchronization for launch and process milestones. Credential scrubbing and escaped terminal output receive focused assertions at their public observable seams.

Group closely related branches in their canonical flow; create a new case only for independent behavior. Use deterministic subprocess fixtures for process behavior and separate real-platform manual qualification. Provider stream framing gets focused protocol fixtures because it is an external wire format. No GUI test matrix, stress infrastructure, arbitrary sleeps, or code-coverage percentage goal.

The scripted provider validates required tool pairing, closed batches, and frozen epoch prefixes instead of accepting arbitrary history. Exercise abrupt crashes with an owned subprocess and an explicit test-only synchronization/abort point, then reopen via the public interface. For storage failures retain real SQLite: use a controlled write-denied connection or a narrowly scoped SQLite I/O failure seam when needed; verify the chosen injection actually fails the intended commit. Do not introduce a general mock store or treat `query_only` as proof of disk-full behavior. Test transient contention separately from permanent persistence failure through the existing persistence flow.

Expected project checks once scaffolded: `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, and `cargo build --release`. Revisit exact checks after the manifest exists. Document a small manual live-model evaluation with fixed fixture tasks: locate a bug, change an interface and its caller, and recover from a failed verification command. Record model/config, observed success, user interventions, usage, and elapsed time. These are evaluations of model behavior, not deterministic CI guarantees.
