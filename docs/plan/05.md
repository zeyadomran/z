## 5. Tools and workspace behavior

Initial model tools:

- `list_files`: workspace-relative entries, ignore generated/VCS directories by default, bounded results and explicit pagination.
- `search_text`: literal search first, bounded matches with paths and line numbers; regex can follow if needed.
- `read_file`: bounded line or byte ranges and a content hash. Reject binary/unsupported encoding with a useful error.
- `apply_patch`: create or edit one UTF-8 text file per call, with expected original hash, exact match semantics, and a preview. No multi-file atomicity claim, fuzzy match, deletion, rename, permission changes, or symlink editing in v1.
- `run_command`: an explicit executable plus argument vector and workspace-relative cwd; use a separate explicit shell-script form only when necessary. Show the exact interpreter/script to the user. Both forms require approval.
- `read_tool_output`: retrieve a bounded range from a stored result handle belonging to this session.

Resolve absolute paths and workspace identity at session creation. Reject traversal, device paths, unsupported network workspaces, and paths resolving outside scope. For new files validate the existing parent. Treat symlinks, junctions, reparse points, hard links, and case-insensitive paths deliberately: reject unsafe/ambiguous write targets, and verify read targets remain in scope. Preflight and recheck at execution; do not promise race-free isolation against hostile concurrent filesystem changes in host mode.

Accept only normal relative tool-path components. On Windows reject rooted/drive-relative forms, colons/alternate streams, reserved device names, trailing dots/spaces, and traversal. Verify opened handles' final paths and apply credential denial to resolved names case-insensitively. Listing/search share read exclusions and never follow links. Built-in writes to `.git` directories or files are denied in v0.1. [Windows path rules](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)

Ignore rules are convenience, not access control. Default-deny common credential files and the harness's own data directory to built-in reads and writes; a user-selected file exception is explicit. This cannot prevent an approved arbitrary host command from reading user-accessible data. Document that limitation rather than presenting filename filtering as a sandbox.

Patches preserve existing newline style and fail if the file changed since the preview. Use a staged replacement appropriate to each OS; verify the final content hash and retain the prior contents/diff for review. If a conflict occurs, reread and propose a fresh patch with fresh approval. Never reset the user's working tree automatically.

Every read hash is SHA-256 of the whole raw file, including range reads. Present editable UTF-8 as LF-normalized text plus BOM/newline metadata; match patches exactly against that view, then restore the original uniform LF/CRLF encoding and BOM. Reject mixed-newline edits in v0.1. New files use an explicit must-not-exist expectation. Detect changes during reads and return conflict rather than a mismatched hash/view. Range reads of larger files can stream the whole-file hash within time/output limits; edits above 1 MiB are rejected. The 256 KiB argument limit intentionally caps one patch/create payload below the file limit.

Use recorded unique staging paths in the target directory. Retry transient Windows sharing violations only within a bounded interval; never ignore ACL preservation errors. Recovery may inspect/clean only artifacts owned by the recorded attempt after preserving reconciliation evidence, never similarly named user files.

For existing files, preserve supported security metadata as well as bytes: Windows ACLs and file attributes, and Unix modes if that platform is qualified. A matching text hash does not prove metadata preservation. Select the native replacement procedure accordingly, fail closed on unsupported preservation, and retain evidence of partial failures. On Windows, evaluate `ReplaceFileW` without flags that ignore ACL merge errors; do not infer durable writes from its unsupported write-through flag. New files use documented parent inheritance. Include original/expected metadata in patch reconciliation. [Windows file replacement](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)

Resolve the executable and interpreter to an absolute launch path before approval. Bind the effective interpreter, script, argument representation, cwd, and environment configuration to the approved action. Direct Windows launch supports ordinary executables with documented argument handling; `.cmd`/`.bat` shims and other interpreters must use an explicit visible interpreter/script specification or be rejected with guidance. Do not silently convert an approved argument vector into a shell command. Revalidate the normalized launch specification at execution; invalidate approval if it changes.

Resolve bare names from approved absolute PATH entries and PATHEXT, excluding implicit workspace lookup; workspace programs require explicit relative paths. Detect available PowerShell versions at session creation. Explicit PowerShell scripts use `-NoProfile -NonInteractive -EncodedCommand`, encoding the exact previewed script as UTF-16LE base64 without changing execution policy. Show interpreter/version and full script before approval. Batch shims such as `npm.cmd` use this explicit script form; do not generate cmd.exe strings from argument vectors. Unsupported argument encoding is a structured error.

Commands run without a terminal and with stdin closed. Programs requiring interaction fail with a useful explanation. Capture stdout/stderr concurrently as bytes; use bounded display decoding and preserve truncation metadata. Proposed limits: 64 KiB model preview, 10 MiB saved output per command, 100 MiB artifacts per session, 1 MiB input text file, and 256 KiB assembled tool arguments. When a command reaches its output-storage cap, terminate it and mark output-limited; continue draining during shutdown to avoid pipe deadlock.

Use a bounded head-and-tail preview and expose `read_tool_output` from M3. Spool raw output to owned per-attempt artifacts as it drains; chunk notifications stay ephemeral. On completion flush artifacts before committing lengths, hashes, truncation/decoding metadata, references, and outcome. Crash remnants are partial and unverified. Decode BOM-marked UTF-16 or valid UTF-8; otherwise use an explicitly selected code page or label a visibly lossy preview. Do not claim reliable detection of arbitrary encodings.
