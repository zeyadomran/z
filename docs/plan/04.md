## 4. Required providers and agent loop

Both providers must reach the same observable coding workflow while retaining their own authentication, wire format, capabilities, continuation encoding, and usage semantics. OpenRouter lands first as an implementation sequence, not as a reduced release scope.

### 4.1 OpenRouter

Start with OpenRouter Chat Completions at `https://openrouter.ai/api/v1/chat/completions` and one configured tool-capable model. Read an `OPENROUTER_API_KEY` reference from host credentials and send it only to the authorized OpenRouter origin. The provider module exposes capabilities including tool calling, accepted content types, context limits, maximum output, and usage availability. Unsupported options must fail clearly; do not silently ignore them. OpenRouter is the gateway identity; its upstream provider is separate routing metadata.

Implement SSE parsing across arbitrary byte boundaries, comment/keepalive handling, indexed `delta.tool_calls` assembly, text deltas, usage, and terminal finish reasons. Treat HTTP errors, midstream error chunks under HTTP 200, output-length exhaustion, and abrupt EOF separately. Accept a completed response only when the selected endpoint's full terminal contract is satisfied; execute nothing from a partial stream. Preserve provider-required `reasoning_details` and opaque tool-continuation data without rewriting it. [OpenRouter streaming](https://openrouter.ai/docs/api/reference/streaming), [reasoning preservation](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)

Pin the provider protocol version and supported options in M1. Treat cumulative usage deltas as an updated snapshot, not amounts to sum repeatedly. Ignore explicitly ignorable new event types while rejecting unsupported executable content. v1 supports multiple calls in one completed response but executes them sequentially.

Discover model metadata from OpenRouter's model catalog, including supported parameters and context limits, and validate the configured model before starting a live turn. Cache metadata with a retrieval time; an unavailable catalog must not cause guesses about capabilities. Expose model slug, reasoning options where supported, token ceilings, upstream allowlist/order, fallback preference, and data-policy configuration. Use `require_parameters: true` for required tool/format options. For initial qualification pin one eligible upstream and disable fallbacks; later user-enabled routing must preserve configured data/capability restrictions. Record the reported model, upstream, generation ID, and usage per attempt. Do not assume opaque continuation data can be moved between providers; fail rather than discard required state when a route is incompatible. [OpenRouter routing](https://openrouter.ai/docs/guides/routing/provider-selection)

### 4.2 Direct ChatGPT plan access

Implementation prerequisite: the [dated direct subscription contract](../chatgpt-subscription/README.md) records verified registration, authentication, request, continuation, and error details as of 2026-11-01. It does not establish actual app/account qualification.

Use Sign in with ChatGPT plan usage for eligible open-source/local apps, with the harness's own registration and a direct Responses adapter. Verify the app distribution model and account eligibility early. A successful sign-in or catalog response alone does not establish usable inference/tool access. Paid or remotely hosted products have a separate access route. [Overview](https://developers.openai.com/siwc/token-sharing-open-source), [registration](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)

Implement a stable host ID, browser authorization with PKCE/state/nonce validation, account/workspace binding, validated identity tokens, and secure token storage/refresh/logout. Persist issued registration identifiers separately from session history. Serialize refresh per account and atomically replace rotated credentials; failed refresh stops that route without switching to paid inference. Clear credentials on logout while preserving local history. A resumed session requires its original authorized account.

Use account-specific model discovery and call `https://api.openai.com/v1/responses` directly with `store: false`, `stream: true`, and the required history in each HTTP request. Preserve required reasoning items and provider call IDs. Encode custom/function tools and their outputs using the preview-supported form, not Chat Completions messages. Only `response.completed` establishes completed inference; treat incomplete, failed, and disconnected streams separately. [Models and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)

Maintain a route-specific capability/request allowlist. The documented preview excludes options including `max_output_tokens` and HTTP `previous_response_id`; do not emit them or promise a provider-enforced output-token cap on this route. Enforce local request/tool/time/output-buffer limits and label upstream limits separately. Handle subscription usage exhaustion/unavailability and reauthentication distinctly. Do not proxy subscription credentials through OpenRouter, reuse another application's registration, or automatically change account/billing mode. [Preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)

Required acceptance: using this harness's sign-in, complete a model request and a harness-owned tool round trip using the wire `function` type under the intended ChatGPT plan; the separate wire `custom_tool_call` type is not required for M1b. Demonstrate refresh/reauthentication behavior, account-bound session resume, and clear quota/error outcomes. The provider remains unavailable until access is proven. If access is denied externally, continue independent engineering work but report the release blocker; do not replace subscription support with API credits or remove it from scope.

### 4.3 Shared turn orchestration

Persist the model ID and request-option configuration alongside provider/account binding. Model changes require a new session in v0.1. Introduce `ContextEpochId`: freeze the serialized system/developer prefix and full tool schemas per epoch, retaining all tools across permission modes while enforcing policy in code. Preserve accepted provider messages and required opaque state verbatim. Append later instruction discoveries as provenance-labelled tool-result data or valid closed-batch messages; do not mutate a prefix under signed history. Schema/prompt changes require a new epoch. Direct-Anthropic beta headers and account-date enforcement claims do not automatically apply to either selected route.

Turn sequence:

1. Acquire the workspace execution lock and persist the accepted prompt before acknowledging it.
2. Snapshot effective instructions and limits, assemble bounded context, and record a model attempt.
3. Stream displayable output while assembling the full response. Commit a completed assistant message only after a valid terminal response.
4. Validate all proposed tools, assign stable call identities, and process them sequentially. v1 does not parallelize tools.
5. For each call, normalize scope and arguments, evaluate policy, and await a specifically bound approval when required.
6. Persist execution intent, execute, store the outcome, and append a matching tool result to conversation history.
7. Continue the model loop until a valid final response, required user input, cancellation, recoverable interruption, or a configured limit.

The durable continuation unit is the completed assistant response and its pending tool batch. Preserve the provider's call IDs separately from local attempt IDs. Store each outcome incrementally. For OpenRouter Chat Completions, preserve the assistant message with its `tool_calls`, then append one `role: tool` message per call with the matching `tool_call_id`; supply the entire completed batch before any next ordinary prompt or model request. Include tool definitions in continuation requests. The ChatGPT plan adapter encodes this same internal batch as Responses tool-call/output items with matching call IDs and retained required reasoning items. Denied, invalid, cancelled-before-start, and deliberately skipped calls receive truthful structured error results. If a command's outcome is unknown, stop and obtain the prescribed user resolution before completing the batch; never invent success. An approval-required exit suspends the batch. Resume must complete or explicitly abandon it, closing every unresolved call with a truthful result, before accepting a new conversational prompt. Already completed calls are never rerun to reconstruct a batch. [OpenRouter tool calling](https://openrouter.ai/docs/guides/features/tool-calling)

Tool errors are structured results the model can use to repair its approach. Configuration/authentication failures terminate the turn with a clear user action. Distinguish a normal final response from output exhaustion, refusal, transport failure, and invalid protocol. Never label an interrupted or truncated response as completed.

Define adapter outcomes before implementation:

- OpenRouter: valid terminal `stop` without executable calls yields final text; `tool_calls` requires complete validated calls. `length` is truncated/context-limited with no execution of that response's calls. Content filtering/refusal, `error`, unknown finish reasons, and abrupt EOF are distinct non-success outcomes. Consume the full endpoint terminal contract; HTTP 200 is insufficient.
- ChatGPT: only `response.completed` permits inspecting complete output for final text or tools. `response.incomplete`, `response.failed`, explicit errors, and disconnected streams never authorize partial calls. Completed refusal content is `refused`, not task success.
- OpenRouter 401/403 require account action; 402 means credits required. For ChatGPT, classify the documented error code and admission status: 401/403 can require identity/grant diagnosis, eligibility or policy action, or route/configuration correction; do not blindly repeat OAuth. Use the [direct-route error mapping](../chatgpt-subscription/responses.md#error-classification). Retry recognized transient throttle/server/transport failures only. Classify subscription quota/unavailability before generic 429 retries. Deterministic validation/continuation failures stop for correction. Recognized context overflow returns recoverable `context_limit` before M5, then may invoke compaction.
- Preserve usage and refused prompts in audit history. Emit `attempt_discarded` when replacing partial streamed text after a retry. Show request activity without requiring visible reasoning. Pin endpoint versions only where documented; do not inject another provider's version headers.

Limit model attempts, tool calls, cumulative output, and elapsed turn time. Proposed initial limits: 30 model requests, 60 tool calls, 20 minutes per turn, 120 seconds per command, and a 5-minute absolute command ceiling. Limits are host-configured, surfaced to users, and cannot be raised by the model. Count compaction and retries against limits.

The turn time budget measures active work, excluding human approval/recovery waits. Persist consumed budget across suspension; restart cannot reset it. A reached configurable limit suspends resumable work with a user-only path to raise the limit. No suspended turn retains running commands.

Retry transient provider failures with bounded backoff and Retry-After support. Limit to two retries before a completed response; discard incomplete assembled tool proposals. A retry can incur extra provider charges. After an authoritative complete response is stored, resume from that response rather than requesting a replacement. Never apply HTTP retry behavior to tool execution.

Handle OpenRouter authentication failure, insufficient credits, throttling, and no eligible upstream as distinct outcomes. Never automatically switch to another paid provider on credit exhaustion. Cancelling the local stream ends local consumption and future tool execution; upstream generation cancellation and billing depend on provider support and cannot be promised universally. Keep unreported usage marked unknown rather than zero. [OpenRouter error and cancellation behavior](https://openrouter.ai/docs/api/reference/streaming)
