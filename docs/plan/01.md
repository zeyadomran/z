## 1. Outcome and scope

Build an original Rust agent engine and CLI inspired by fx. A user selects a local repository, submits a coding task, observes streamed progress, approves edits and commands, and receives a result supported by actual tool output. Sessions survive application restarts. The engine is reusable without terminal dependencies.

The first release is a supervised local developer tool for one user, with one active turn per workspace. v0.1 targets Windows; Linux and macOS are later implementation and qualification milestones. A working directory, process group, or Windows Job Object is not a security sandbox. Version one must describe command execution as running with the current user's host privileges.

Proposed defaults, subject to product preference rather than implementation ambiguity:

- CLI first; a desktop or web interface is deferred.
- Native Rust engine, not a wrapper around fx or another coding agent.
- OpenRouter is a required v0.1 provider and the first concrete implementation target. Use its Chat Completions HTTP interface with an OpenRouter API key and a configurable model slug. Qualify one tool-capable model first, then additional model families through the same adapter. Reviewer models are unrelated to runtime defaults.
- Direct ChatGPT plan access is also required in v0.1. Implement the supported Sign in with ChatGPT flow and a dedicated Responses adapter. The Rust harness owns the agent loop and tools. A Codex wrapper, a paid OpenAI API key, or subscription-derived API credits does not satisfy this requirement. Validate app/account access early; an external eligibility failure blocks a complete v0.1 release rather than silently dropping the feature.
- File reads within the selected workspace run automatically after the user starts a session. Every edit and shell command requires approval. No automatic command-risk classifier in v1.
- Session data is local. With OpenRouter, relevant context goes to OpenRouter and its selected upstream model provider; with ChatGPT plan access, it goes directly to OpenAI. Routing/data-policy choices must be explicit. No telemetry by default.
- No hosting requirement, autonomous Git push/merge, browser automation, network MCP integrations, subagents, or persistent background commands in v1. Never reuse another app's OAuth registration or silently change billing routes.

First demonstrable task: explain a small fixture repository, locate a simple bug, propose a patch, obtain approval, apply the patch, obtain approval for a verification command, run it, and report the observed outcome. Reopen that conversation in a fresh process.
