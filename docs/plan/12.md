## 12. Later capabilities and decision gates

After the two required providers ship, consider additional direct API providers, MCP/skills, ACP for editor integration, and a desktop interface. Additional supported model families through OpenRouter do not require separate gateway adapters. Protocol and permission design must precede exposing tools to external plugins. Add subagents only with separate workspace ownership, explicit budgets, and cancellation/recovery semantics.

Separately, eligible Pro/Business subscriptions may claim API credits for a linked OpenAI API organization. That uses a normal OpenAI API-key adapter and metered credits, not OpenRouter credit or unlimited subscription inference. Account eligibility and activation remain unverified. [Subscription API credits](https://developers.openai.com/api/docs/guides/chatgpt-api-credits)

A sandboxed mode is a separate milestone requiring real filesystem/network restrictions, credential separation, and escape-focused qualification. It must fail closed when its sandbox backend is absent. Do not rebrand supervised host execution as sandboxed execution.

Confirmed requirements: OpenRouter and direct ChatGPT plan access in Windows CLI v0.1. Open choices: product name (temporary `harness`), qualified OpenRouter model/upstream and account-available ChatGPT model, and app distribution consistent with subscription eligibility. Pricing, model IDs, dependency versions, and signing/distribution need implementation-time verification. ChatGPT access remains externally unverified and release-blocking if unavailable. Linux/macOS have separate later milestones.
