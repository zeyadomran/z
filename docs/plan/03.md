## 3. Rust implementation choices

- Tokio for asynchronous I/O, timers, channels, and coordination. Run blocking database work on a dedicated blocking worker; never hold a SQLite transaction across network or process awaits. [Tokio](https://tokio.rs/)
- reqwest with explicit timeout, TLS, redirect, and proxy configuration for model HTTP requests. Do not forward credentials across origins. [reqwest](https://docs.rs/reqwest/latest/reqwest/)
- Serde and serde_json for versioned persisted records and provider/tool messages. Reject malformed tool arguments and unsupported required fields. [Serde](https://serde.rs/)
- rusqlite with a bundled, patched SQLite release for reproducible local packaging. Record the actual selected version and its security review at implementation time. [rusqlite](https://docs.rs/rusqlite/latest/rusqlite/)
- clap for command parsing. Keep the first UI line-oriented; no full-screen TUI or PTY requirement. [clap](https://docs.rs/clap/latest/clap/)
- Structured local diagnostics with tracing; record IDs, statuses, durations, and usage rather than raw credentials or prompts by default. [Tokio tracing](https://tokio.rs/)

Pin a supported stable Rust toolchain and commit Cargo.lock for the executable. Choose dependency versions when implementing, after checking compatibility and licenses. Native OS calls for process ownership live in a small reviewed module. No broad agent framework is required.

Credential-bearing HTTP clients disable redirects with `Policy::none()` and mark authorization headers sensitive. Use separate connect and idle-read timeouts; the engine deadline bounds the entire stream. Default to direct access, with a user-configured proxy as an explicit option. OAuth navigation occurs in the browser, not by forwarding inference credentials through redirects. [reqwest settings](https://docs.rs/reqwest/latest/reqwest/struct.ClientBuilder.html)
