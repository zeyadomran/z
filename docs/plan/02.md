## 2. Architecture and ownership

Use a Cargo workspace with two crates initially: `harness-core` and `harness-cli`. Keep core modules private unless the CLI needs their types. Avoid a separate crate per module and generic plugin frameworks.

The engine owns the active turn, policy enforcement, persistence, tool execution, and cancellation. The CLI owns input and presentation. The CLI cannot execute tools outside engine checks.

Core modules:

- `engine`: a single coordinator that owns turn state and serializes transitions. It assembles requests, consumes provider output, authorizes completed tool calls, and produces events.
- `provider`: separate OpenRouter Chat Completions and ChatGPT plan Responses adapters, plus a deterministic scripted provider. Preserve provider-required content blocks and opaque continuation data. The shared interface normalizes outcomes without assuming identical wire schemas or capabilities.
- `auth`: OpenRouter credential references and ChatGPT registration, validated account identity, secure token rotation, logout, and account-specific model discovery. Expose authorized request credentials only to the matching provider origin; keep secrets outside persisted conversations and tool environments.
- `workspace`: scope resolution, instruction loading, bounded file search/read, and conflict-aware patches. Do not expose unrestricted filesystem handles to model-generated arguments.
- `execution`: supervised process lifecycle, concurrent stdout/stderr draining, output limits, timeout, and process-tree shutdown. Windows and Unix implementations satisfy the same observable contract.
- `policy`: deterministic decisions for a normalized action. Produces allow, deny, or request-approval; neither model output nor repository instructions can authorize an action.
- `store`: SQLite transactions, schema versions, durable events, tool attempt state, and compaction checkpoints. Use a concrete store, not an abstract database framework.
- `context`: request budgeting, complete-message selection, instruction hierarchy, output handles, and compaction preparation.

Initial public interface, described behaviorally rather than as finalized Rust signatures:

- Open an engine using workspace, provider, policy, limits, and a local data directory.
- Create or reopen a session; submit one user prompt and obtain a turn handle.
- The handle exposes events, approval responses bound to request IDs, cancellation, and a terminal outcome.
- List sessions and read their saved history. Session deletion is explicit and refuses an active session.

Domain types include `SessionId`, `TurnId`, `ToolCallId`, `AttemptId`, `ApprovalId`, `WorkspaceIdentity`, `ActionDigest`, and `EventSequence`. IDs are stable across restart. Persist schema version, provider, and account/workspace binding using a local credential reference, never token values. A session's provider or authenticated account cannot silently change on resume. v0.1 uses a new session for a provider/account change; it does not transfer opaque history or approvals across providers.

Events distinguish model text deltas, completed assistant messages, tool proposals, approvals requested/resolved, tool start/output/finish, usage, and terminal outcomes. Durable state is authoritative; UI delivery is not an execution acknowledgment. Text deltas may be ephemeral, but completed messages and tool transitions are durable. Use bounded channels; never drop approval or terminal events silently.

Cancellation has an independent signal, not a slot in the presentation queue. Pipe readers, process supervision, deadlines, and cleanup never await UI consumption. Coalesce ephemeral text/output notifications when the UI falls behind; durable events remain queryable by sequence. If the observer disconnects or drops the turn handle, request cancellation rather than detaching work. Expose explicit asynchronous shutdown that joins cleanup; dropping the engine signals cancellation but cannot promise completed asynchronous cleanup. The CLI must await shutdown before exiting. A paused observer must not prevent deadlines or cleanup from running.
